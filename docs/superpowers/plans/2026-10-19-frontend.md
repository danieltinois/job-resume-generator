# Frontend and Delivery Implementation Plan (Plan 3 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Angular app from spec §6 on top of the Plan 2 API, package the whole product for `docker compose up`, prove it end to end with Playwright, and retire the Python CLI.

**Architecture:** An Angular 22 SPA in `frontend/` (standalone components, signals, `OnPush`, typed Reactive Forms, Angular Material). API types are generated from the backend's OpenAPI spec, which is committed and checked for drift. nginx serves the SPA and proxies `/api`, `/oauth2` and `/login/oauth2` to Spring, so the browser sees one origin and the refresh cookie stays `SameSite=Strict`. Compose runs PostgreSQL, Mailpit, backend and frontend.

**Tech Stack:** Node 22.23.3 (pinned in `.nvmrc`; Angular CLI 22 needs ≥ 22.22.3), Angular 22.2 + Angular Material/CDK 22.2, Vitest (Angular CLI default runner), angular-eslint 22, `openapi-typescript` 7.13, Playwright 1.64, nginx 1.29-alpine, `eclipse-temurin:21-jre` + Typst 0.15.0 for the backend image.

**Spec:** `docs/superpowers/specs/2026-10-19-spring-angular-migration-design.md` (§6 frontend, §11 local run). Plans 1–2 under `docs/superpowers/plans/`.

## Global Constraints

- Everything from Plans 1–2 still holds (AGENTS.md).
- UI strings exist in PT-BR and EN, chosen from the browser language with a switch in the toolbar. **Deviation from the spec's "Angular i18n"**: `@angular/localize` builds one bundle per locale and cannot switch at runtime; a small signal-based `I18n` service with two typed dictionaries can, and a missing key fails the type check.
- Components are standalone, `ChangeDetectionStrategy.OnPush`, state in signals; HTTP results converted with `toSignal` or held in signals, no manual subscriptions left open.
- The access token lives only in memory (a signal in `AuthStore`); nothing auth-related goes to `localStorage`/`sessionStorage`.
- One refresh at a time across tabs: `navigator.locks.request('resume-refresh', …)`.
- API types come only from `frontend/src/app/core/api/schema.d.ts`, generated from `docs/api/openapi.json`; hand-written duplicates of API shapes are not allowed.
- Ids for new profile items are generated client-side in the backend's format: `<prefix>_<8 lowercase hex>` (`exp_`, `ach_`, `prj_`, `edu_`, `cat_`), via `crypto.getRandomValues`.
- Accessibility: every form control has a visible label, focus is visible, and drag-and-drop lists also offer move-up/move-down buttons.
- No test is skipped; the e2e test runs in CI.

## Review Focus

1. **The access token expires in the middle of editing** (15 min) → the next request refreshes once and retries, and the pending autosave is not lost.
2. **Several tabs open at once, or one is restored from the session** → a single refresh runs (Web Lock); no tab gets signed out.
3. **Autosave hits 409 (profile saved in another tab)** → a dialog offers "reload theirs" or "keep mine and overwrite"; local edits are never silently discarded.
4. **Fast clicking in the review screen** → only the latest preview is shown; older responses are cancelled (`switchMap`) and never overwrite a newer PDF.
5. **A long profile** (10 experiences × 10 bullets) → typing stays responsive: collapsed experiences render no form controls, and autosave is debounced.

Each has a test in its owning task (marked *Review Focus*).
